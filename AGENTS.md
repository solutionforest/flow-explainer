# flow-explainer

Turns pasted GitHub markdown (Mermaid flowchart, sequence, state, class, ER, gantt, pie, mindmap, journey, timeline, quadrantChart, gitGraph, xychart, sankey, block, architecture, C4, kanban, packet, requirementDiagram + numbered list as narration) into an animated step-by-step walkthrough for clients.

- `index.html` — 2D isometric SVG version. Also served from zo.space API route `/flow-explainer` (not linked publicly).
- `3d.html` — Three.js version (real 3D blocks, rotatable camera). Also served via zo.space (route `/flow-explainer/:file`; Three.js 0.187.0 jsDelivr-minified in `vendor/`, imported as `./vendor/three.module.js` and served by route `/flow-explainer/vendor/:file`).
- Both files are standalone and edited directly; they share the same markdown parser, layout, panel, timeline and `#c=` client-link code (copied, not imported). The parser block (`/* ---------- markdown` … `/* ---------- layout`) and the diagram styles block are edited in `index.html` only, then copied with `python3 tools/sync-parser.py` (`--check` to verify). Non-parser fixes (render, buildScene, iconFor) still go into both files by hand.
- Every diagram type is converted into the same `{nodes,links,steps,groups}` graph. Extra node fields: `note`, `icon` (forced emoji), `iconFallback`, `ci` (palette index), `hk` (height factor: pie, journey, xychart, sankey, packet). Graph flags: `fixed` (parser set `gx/gy`, skip `layout()`; non-pie fixed parsers call `routeFixed()` to give links `pts`: timeline, quadrant, git, xychart, block, kanban, packet), `noZones` (colour groups without zone slabs, mindmap), `diagramTitle` (used when the markdown has no heading).
- Both read the same `localStorage` key `flowx.md`; the 2D/3D button keeps the URL hash and works with both `/flow-explainer` ↔ `/flow-explainer/3d` and `index.html` ↔ `3d.html` (static hosting).
- Public repo: https://github.com/solutionforest/flow-explainer (MIT). README images in `docs/images/` were made with the Snapshot button; sample inputs in `examples/`.
- 📸 Snapshot (edit mode only): modal exports a README PNG (title header, optional step-number badges, group legend) + "Copy README text" (image link + numbered steps). Overlap checker lists label/box/step-number collisions; "minor" = label sitting on an arrow line.
  - 2D: `render()` places node labels (lift/side shift), arrow labels and badges greedily to avoid collisions; export serialises the SVG with scene CSS inlined.
  - 3D: `analyse(cam)` computes label/box screen rects analytically (must match `.lab` CSS transforms); export draws HTML labels onto the WebGL frame and crops to content; "Find a clean angle" scores 64 camera angles. `window.__fx` is a test handle.

- Site look: Solution Forest colours (teal `#007c90`, amber `#fcaf17`), Inter / Raleway self-hosted in `vendor/` (OFL). UI CSS uses `--brand`, `--ink`, `--line`… tokens; diagram CSS uses only `--d-*` tokens, which `useStyle()` sets from the active diagram style.
- Diagram styles: `STYLES` (original = default and must stay pixel-identical to the old look, teal, line, blueprint, glass) in the shared block `/* ---------- diagram styles + settings` … `end of diagram styles + settings`, synced to 3d.html by `tools/sync-parser.py`. Chosen style is saved in `localStorage` `flowx.style` and added to client links as `&s=<key>` (`#c=<data>&s=teal`); `restyle()` in each page re-renders. 2D reads `DS.edge/ink/blocks/sw/opacity…` in `prism()`/`render()`; 3D reads `DS.mat/edge3d/outline/ground…` in `blockMat()`/`render()`.
- UI: ⚙ Settings popover (slide-out sheet ≤820px) with diagram style + 3D/2D; Copy client link opens a popover with the privacy notes (not uploaded / not encrypted); All steps is a `<details>` stepper (`stepsHtml()`), folded by default on phones. Header: **New** (empty editor, `#tplNew` template via “Use template”), **Examples** select (`#exHead`, mirrors `#exSel`), brand button opens the **About** dialog (`#about`, also footer “About”).
- Branding: footer of both pages shows "GitHub · MIT License · Made by Solution Forest" (Solution Forest links to https://solutionforest.net/), plus a GitHub button in the header. No SF logo. Do not add personal demo-site links to the README or repo.
- Live site: https://flow-explainer.laravel.cloud/ (Laravel Cloud, deployed from `main`, served by `server.js`). SEO/social: `<head>` of both pages has description, canonical, Open Graph + Twitter card (`og-image.png`, 1200×630, made from the README cover), JSON-LD `WebApplication`; root files `favicon.svg/.ico`, `apple-touch-icon.png`, `site.webmanifest`, `robots.txt`, `sitemap.xml` use that domain. The built-in demo keeps the descriptive `<title>`; loaded diagrams set it to their own title.
