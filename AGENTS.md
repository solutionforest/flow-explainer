# flow-explainer

Turns pasted GitHub markdown (Mermaid flowchart, sequence, state, class, ER, gantt, pie, mindmap, journey, timeline, quadrantChart, gitGraph, xychart, sankey, block, architecture, C4, kanban, packet, requirementDiagram, radar, treemap, zenuml + numbered list as narration) into an animated step-by-step walkthrough for clients.

- `index.html` — 2D isometric SVG version. Also served from zo.space API route `/flow-explainer` (not linked publicly).
- `3d.html` — Three.js version (real 3D blocks, rotatable camera). Also served via zo.space (route `/flow-explainer/:file`; Three.js 0.187.0 jsDelivr-minified in `vendor/`, imported as `./vendor/three.module.js` and served by route `/flow-explainer/vendor/:file`).
- Both files are standalone and edited directly; they share the same markdown parser, layout, panel, timeline and `#c=` client-link code (copied, not imported). The shared core (`/* ---------- shared core:` … `/* ---------- end of diagram styles + settings`: helpers, markdown + Mermaid parsers, layout, diagram styles/settings UI) is edited in `index.html` only, then copied with `python3 tools/sync-parser.py` (`--check` to verify). Layout spacing differs per page via `IS_3D_PAGE`. Non-parser fixes (render, buildScene, iconFor) still go into both files by hand.
- Every diagram type is converted into the same `{nodes,links,steps,groups}` graph. Extra node fields: `note`, `icon` (forced emoji), `iconFallback`, `ci` (palette index), `hk` (height factor: pie, journey, xychart, sankey, packet). Graph flags: `fixed` (parser set `gx/gy`, skip `layout()`; non-pie fixed parsers call `routeFixed()` to give links `pts`: timeline, quadrant, git, xychart, block, kanban, packet), `noZones` (colour groups without zone slabs, mindmap), `diagramTitle` (used when the markdown has no heading).
- Both read the same `localStorage` key `flowx.md`; the 2D/3D button keeps the URL hash and works with both `/flow-explainer` ↔ `/flow-explainer/3d` and `index.html` ↔ `3d.html` (static hosting).
- Public repo: https://github.com/solutionforest/flow-explainer (MIT). README images in `docs/images/` were made with the Snapshot button; sample inputs in `examples/`.
- 📸 Snapshot (edit mode only): modal exports a README PNG (title header, optional step-number badges, group legend, optional credit strip `drawCredit()`: icon + “Made with Flow Explainer” + `flow-explainer.laravel.cloud`, on by default) + "Copy README text" (image link + numbered steps). Overlap checker lists label/box/step-number collisions; "minor" = label sitting on an arrow line.
  - 2D: `render()` places node labels (lift/side shift), arrow labels and badges greedily to avoid collisions; export serialises the SVG with scene CSS inlined.
  - 3D: `analyse(cam)` computes label/box screen rects analytically (must match `.lab` CSS transforms); export draws HTML labels onto the WebGL frame and crops to content; "Find a clean angle" scores 64 camera angles. `window.__fx` is a test handle.

- Site look: Solution Forest colours (teal `#007c90`, amber `#fcaf17`), Inter / Raleway self-hosted in `vendor/` (OFL). UI CSS uses `--brand`, `--ink`, `--line`… tokens; diagram CSS uses only `--d-*` tokens, which `useStyle()` sets from the active diagram style.
- Diagram styles: `STYLES` (original = default and must stay pixel-identical to the old look, teal, line, blueprint, glass) in the shared block `/* ---------- diagram styles + settings` … `end of diagram styles + settings`, synced to 3d.html by `tools/sync-parser.py`. Chosen style is saved in `localStorage` `flowx.style` and added to client links as `&s=<key>` (`#c=<data>&s=teal`); `restyle()` in each page re-renders. 2D reads `DS.edge/ink/blocks/sw/opacity…` in `prism()`/`render()`; 3D reads `DS.mat/edge3d/outline/ground…` in `blockMat()`/`render()`.
- UI: ⚙ Settings popover (slide-out sheet ≤820px) with diagram style + 3D/2D; Copy client link opens a popover with the privacy notes (not uploaded / not encrypted); All steps is a `<details>` stepper (`stepsHtml()`), folded by default on phones. Header: **New** (empty editor, `#tplNew` template via “Use template”), **Examples** select (`#exHead`, mirrors `#exSel`), brand button opens the **About** dialog (`#about`, also footer “About”).
- Branding: footer of both pages shows "GitHub · MIT License · Made by Solution Forest" (Solution Forest links to https://solutionforest.net/), plus a GitHub button in the header. No SF logo. Do not add personal demo-site links to the README or repo.
- Live site: https://flow-explainer.laravel.cloud/ (Laravel Cloud, deployed from `main`, served by `server.js`). Backup: https://solutionforest.github.io/flow-explainer/ (GitHub Pages via `.github/workflows/pages.yml`, public files only). SEO/social: `<head>` of both pages has description, canonical, Open Graph + Twitter card (`og-image.png`, 1200×630, made from the README cover), JSON-LD `WebApplication`; root files `favicon.svg/.ico`, `apple-touch-icon.png`, `site.webmanifest`, `robots.txt`, `sitemap.xml` use the Cloud domain. The built-in demo keeps the descriptive `<title>`; loaded diagrams set it to their own title.
- Embed (still static): `/embed` and `/embed/3d` serve the same pages with `body.embed` (+ client) chrome — hides About/Share/GitHub/Settings; keeps title, scene picker, Play, panel, 2D/3D. Share popover has iframe HTML or script-tag snippets (`embedCode()` / `embedScript()`) plus **Copy embed link** (`embedLink()`). Standalone loader: root `embed.js` (also on Pages); defaults to no step text (`data-text="0"` / `&t=0`). On static hosts (`isStaticHost()`: `*.github.io`, `*.html`, `file:`) links use `index.html?embed=1` / `3d.html?embed=1` instead of `/embed`. Laravel Cloud must allow framing (`response_headers.frame=all`) for iframes.
- Icons: Settings → Icons (Show/Hide) toggles the emoji on blocks (`ICONS_ON`, `localStorage` `flowx.icons`, client links carry `&i=0` when hidden); renderers call `ICONS_ON?iconFor(n):''`.
- radar (`parseRadar`, points on a circle, `noZones`), treemap (`parseTreemap`, kanban-like columns per top section) and zenuml (`parseZen`, sequence model with a call stack) were added after the first 20 types.
- Code checks: `npm run check` = sync check + ESLint (`eslint.config.mjs`) + `tsc -p tsconfig.basic.json` (checkJs, must be 0 errors) + strict TS with baseline (`tools/typecheck-strict.mjs`, `tsc-baseline.json`; no new errors allowed, run `npm run typecheck:baseline` after fixing some). Page scripts are copied to `.check/` with line numbers kept (`tools/extract-scripts.mjs`). CI: `.github/workflows/check.yml`. In index.html the play-stop function is `stopPlay()` (avoids shadowing `window.stop`).
- Strict typing: the shared core must have 0 TypeScript strict errors (JSDoc typedefs `FxNode`, `FxLink`, `Step`, `Graph`, `Scene`, `MdDoc`, `DiagramStyle`…); `tools/typecheck-strict.mjs` fails on any core error regardless of the baseline. server.js / tools / tests are strict via `tsconfig.node.json`.
- Tests: `npm test` (node:test) — `tests/load-core.mjs` evaluates the shared core from index.html in a VM; `tests/parser.snapshot.json` pins parser output (`npm run test:update` to accept intended changes); `tests/server.test.mjs` covers routes incl. `/embed`, `/embed/3d`, trailing slashes, assets under sub-paths and private files.
- Circuit style (`circuit`): `chips` (2D `chipDetail()`, 3D `chipGeo()`), `flat` (block height factor), `labMono`/`labUpper` (plain monospace capital labels, `--d-lab`).
- server.js exports `resolveFile`/`handle` (listens only when run directly). Links are built without trailing slashes (`pageUrl()`): `/3d/` used to 404 and `/embed/…/` broke relative asset URLs.
